# Architecture

How the parts of `src/rac/` fit together once the project is complete.

## Components

```mermaid
flowchart LR
    cfg[("Run config<br/>configs/*.yaml")]
    bench[("RepoBench v1.1 /<br/>CrossCodeEval")]
    out[("Results<br/>outputs/&lt;run&gt;/")]

    subgraph runnerBox["Experiment runner"]
        runner["eval/runner.py"]
        data["data/<br/>dataset loaders"]
        prompt["prompt.py"]
        model["models/<br/>4-bit code model"]
        metrics["eval/metrics.py<br/>EM, edit similarity"]
    end

    subgraph contextBox["Context builder"]
        build["build_context"]
        methods["methods.py<br/>none, BM25, signatures, oracle"]
        retrieval["bm25.py, tokenize.py<br/>retrieval"]
        fill["fill.py<br/>fill to N tokens"]
    end

    subgraph selectorBox["Selector"]
        feats["selector/features.py"]
        train["selector/train.py<br/>CPU classifier"]
    end

    stats["eval/stats.py<br/>paired significance tests"]

    cfg --> runner
    bench --> data --> runner
    runner -->|"example, method, N"| build
    build --> methods
    methods --> retrieval
    methods --> fill
    build -->|"context"| prompt
    prompt --> model --> metrics --> out
    out --> stats
    out -->|"best method per example"| train
    feats --> train
    retrieval -.->|"BM25 scores"| feats
```

### Reading the diagram

- **Experiment runner** loops over examples, methods, and context budgets N. Each completion is
  built from the context, generated by the model, scored, and written to `predictions.jsonl`.
- **Context builder** is the boundary between the runner and retrieval. `build_context` picks a
  method from its registry and guarantees the result fits in N tokens.
- **Selector** learns from the results which method and budget work best for each example,
  using features available before generation (including BM25 scores).
- **Stats** compares methods on the same examples to decide which differences are real.
- `types.py` (`Example`, `Snippet`, `ResultRow`) is the shared data contract used by every box.

## Sequences

### One experiment run

`python -m rac run configs/<run>.yaml` produces one result row per example, method, and budget.

```mermaid
sequenceDiagram
    participant CLI as cli.py
    participant Runner as eval/runner.py
    participant Data as data/
    participant Ctx as build_context
    participant Prompt as prompt.py
    participant Model as models/
    participant Metrics as eval/metrics.py
    participant Out as outputs/

    CLI->>Runner: run(config)
    Runner->>Data: load sampled examples
    Data-->>Runner: examples
    Runner->>Model: load 4-bit model
    loop each example x method x budget N
        Runner->>Ctx: build_context(example, method, N, tokenizer)
        Ctx-->>Runner: snippets (at most N tokens)
        Runner->>Prompt: build_prompt(example, snippets)
        Prompt-->>Runner: prompt
        Runner->>Model: generate(prompt)
        Model-->>Runner: completion, latency
        Runner->>Metrics: score(completion, target)
        Metrics-->>Runner: EM, edit similarity
        Runner->>Out: append ResultRow to predictions.jsonl
    end
    Runner->>Out: write summary.json
```

### Building context

What happens inside `build_context` for a retrieval method.

```mermaid
sequenceDiagram
    participant Runner as eval/runner.py
    participant Ctx as build_context
    participant Method as methods.py
    participant BM25 as bm25.py
    participant Fill as fill.py

    Runner->>Ctx: build_context(example, method, N, tokenizer)
    Ctx->>Method: look up method in registry
    Method->>BM25: rank candidates against the cursor's last lines
    BM25-->>Method: ranked snippets
    Method->>Fill: fill_to_cutoff(ranked, N, tokenizer)
    Fill-->>Method: snippets that fit in N tokens
    Method-->>Ctx: snippets
    Ctx->>Ctx: check token count is at most N
    Ctx-->>Runner: snippets (or BudgetExceeded)
```

### Training and evaluating the selector

The selector learns from finished runs, then is compared against fixed choices.

```mermaid
sequenceDiagram
    participant Out as outputs/
    participant Train as selector/train.py
    participant Feats as selector/features.py
    participant Stats as eval/stats.py

    Train->>Out: read predictions.jsonl from all runs
    Out-->>Train: result rows
    Train->>Train: label each example with its best method and smallest budget
    loop each example
        Train->>Feats: extract(example)
        Feats-->>Train: features (computed before generation)
    end
    Train->>Train: fit classifiers on CPU, split by repository
    Train->>Stats: compare against best fixed method, random, and oracle
    Stats-->>Train: paired differences with confidence intervals
```
